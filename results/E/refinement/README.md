# Stream E improvement: boundary-preserving, uncertainty-guided depth refinement

**Built on the group's final model**, Depth Anything V2 Small + Smooth Depth-Dependent Bias Correction (`results/Depth Anything V2`). It uses the same official code and ViT-S weights, `infer_image(input_size=518)`, and its saved parameters, which are read and never modified. ## Method

1. **Perturbation uncertainty.** The group model runs on 6 versions of each frame: original, horizontal flip, brightness ×1.1, brightness ×0.9, input size 476 and 560. Each output gets the group's linear + smooth calibration. Uncertainty per pixel = std / mean of the 6 depths.
2. **Edge-aware refinement.** A guided filter (He et al., 2013) smooths depth using the grey image as guide, so smoothing stops at visible tissue edges such as folds.
3. **Uncertainty-guided blending (proposed).** refined = w · guided(D) + (1 − w) · D, with w rising linearly from 0 to 1 between the 50th and 90th percentile of dev uncertainty. Confident pixels and boundaries are left unchanged; only uncertain regions are refined.
4. **Variant 4.** The same blending applied to the mean of the 6 calibrated predictions, which are already computed for the uncertainty.

## Protocol

- Same mask (`gt_raw > 0`) and aggregation (frame means; RMSE = √mean per-frame MSE) as the group's final table.
- Settings were chosen on dev only: calibration refitted on 0000–0044 exactly as the group did, scored on 0045–0060, criterion AbsRel. Grid: uniform σ ∈ {2, 4, 8, 16}; guided-filter r ∈ {4, 8, 16, 32}, ε ∈ {1e-4, 1e-3, 1e-2}; thresholds (p50, p90), (p70, p95) or (p85, p99). All results are in `tuning_dev_val.csv`.
- Chosen settings (`chosen_settings.json`): uniform σ = 16; edge-aware r = 8, ε = 1e-3; uncertainty-guided r = 32, ε = 1e-2, thresholds p50–p90.
- Variant 4 was added after seeing the dev ablation (the ensemble control was strong) but **before** any test run, reusing the frozen settings of variant 3.
- Test uses the group's final parameters; uncertainty thresholds come from the 61 dev frames. Test was run once.
- "Boundary" pixels: top 10% of GT log-depth gradient (eroded mask). These are used for evaluation only.

## Does the uncertainty track the error?

| | Spearman ρ (uncertainty vs AbsRel) | AUSE ↓ | AURG ↑ (> 0 = better than random) |
|---|---|---|---|
| Dev 0045–0060 | 0.62 | 0.048 | 0.081 |
| Test | 0.34 | 0.110 | 0.036 |

See `sparsification.png`. On test, removing the 40% most uncertain pixels lowers AbsRel from 0.28 to 0.21. Beyond about 60%, the remaining "confident" pixels have higher error: the model is consistently wrong in the far-lumen centre, and every perturbation agrees on that wrong answer.

## Findings

1. **Among the filters, only uncertainty-guided refinement improves every metric.** Uniform smoothing lowers AbsRel a little but worsens MAE, RMSE and δ. A global edge-aware filter changes almost nothing. Restricting refinement to uncertain regions gives a small but consistent gain (AbsRel −1.1%), including at boundaries (−1.1%).
2. **The gain from filtering alone is small because the error is mostly smooth and large-scale.** Whole regions are offset, rather than locally noisy. Filtering cannot fix region-wide bias.
3. **The perturbation passes are worth more as an ensemble.** Averaging them gives most of the improvement (AbsRel −7.7%), and uncertainty-guided refinement on top adds a further gain. Variant 4 is best on every metric (AbsRel −8.7%, δ +0.046, boundary AbsRel −5.2%).
4. **The uncertainty is a useful but imperfect reliability signal.** It flags unreliable periphery and near-wall regions (ρ = 0.62 on dev), but weakens under the dev→test texture shift (ρ = 0.34) and misses systematic errors where all perturbations agree. This is the main risk the idea anticipated. It indicates variance, not bias.
5. **Cost.** 6 forward passes at about 83 ms each is about 0.5 s per frame on Apple M4 Pro, versus about 0.08 s for the base model. A smaller perturbation set would trade accuracy for speed.
